1 Skill — 可复用的独立能力单元

概念定义：Skill = 一份 .md 文件，告诉 AI「遇到 X 场景 → 按 Y 流程执行」。可独立调用、独立迭代、组合使用。

将竞品情报处理链路拆分为 5 个独立 Skill：

competitive-intel-collect

触发：「采集 XX 产品最新动态」
调度 Playwright / WebSearch 采集多源信息

competitive-intel-extract

触发：采集到原始信息后
GLM 视觉 OCR → 结构化提取变化点

competitive-intel-distill

触发：提取完变化点后
去重 → 判断是否新方法论 → 写入知识库

competitive-intel-index

触发：有新条目入库后
更新轻量索引 + 主题检索树

competitive-intel-report

触发：「出本周竞品简报」
从知识库检索 → 结构化输出简报 / PPT

🆚 与一次性 Prompt 的对比

维度一次性 Prompt封装为 Skill
可复用性每次重新写指令一次定义，永久调用
迭代优化改 prompt 全靠记忆独立修改单个 Skill
团队共享复制粘贴聊天记录git 分发 .md 文件
质量稳定性每次输出参差不齐Spec 约束保证一致性

2 Spec — 约束规则，保证输出不跑偏

概念定义：Spec = 给 AI 画边界——「必须包含什么、不能做什么、优先级是什么、输出格式是什么」。

📌 信息标注规则

每条信息必须包含：产品名 + 时间 + 变化类型 + 一句话摘要 + 重要度

⚡ 优先级规则

P0 定价/API 变化（直接影响客户决策）
P1 功能/产品策略变化
P2 人事/品牌/PR

🔄 去重规则

同一产品同一变化的多次报道合并为一条，标注所有信息来源

⏰ 时效规则

超过 3 个月的 P2 信息自动标记为 [历史归档]

⚠️ 为什么 Spec 重要

没有 Spec，AI 会把每天的市场行情、重复信息都写进知识库 → 三个月后就膨胀到不可用。
有了 Spec，知识库始终保持精炼、可用、可信。

3 Loop — 循环流水线，越跑越强

概念定义：Loop = 同样的流程不断重复，每次输入自动走一遍管道，输出反哺下一次输入。不是「跑一次就完了」，而是「持续运行的引擎」。

4 Multi-Agent 协作 — 分工干活，互不干扰

概念定义：Multi-Agent = 多个 AI 子代理并行执行不同任务，各自负责独立模块，最后汇总结果。

场景：同时追踪 10 家 AI 产品（7 家中国 + 美国御三家）的最新动态

🧠 主 Agent（编排者）
↓ ↓ ↓ ↓ ↓
智谱 文心 豆包 Kimi 千问
DeepSeek MiniMax OpenAI Anthropic Google
↓
📊 Agent F — 对比分析 → 写入知识库

效率对比

模式采集 10 家产品出对比报告
手动操作~120 分钟~90 分钟
单 Agent 串行~40 分钟~30 分钟
10 Agent 并行（两轮）~12 分钟~20 分钟

💡 核心技术点

  • 每个 Agent 有独立的上下文窗口，互不干扰
  • 主 Agent 只负责编排和汇总，不参与具体采集
  • 这是「编排者模式」（Orchestrator Pattern），不是简单的多开窗口

⚡ 系统工作流演示

场景：本周竞品情报采集

Step 1：触发采集

用户："采集本周 10 家 AI 产品的动态（7 家中国 + 美国御三家）"

Step 2：编排层自动分配

主Agent → 分解为 5 个采集Agent → 并行执行
  每个Agent自动选择工具：
    官网页面  → Playwright MCP 截图
    新闻动态  → WebSearch
    白皮书/报告 → convertertomarkdown MCP

Step 3：提取层处理

5个Agent采集完成 → 汇总到提取Agent
  → GLM 视觉 MCP OCR 截图文字
  → Claude 按 Spec 结构化：产品/时间/类型/摘要/重要度

Step 4：蒸馏层入库

对照 Spec 规则：
  去重：同产品同变化合并
  分级：定价变化 → P0，功能更新 → P1，PR → P2
  入库：新方法论写入 kb，已有内容跳过
  索引：更新 index.md

Step 5：输出报告

用户："出本周竞品简报"
→ report Skill 从 kb 检索 → 结构化输出：
  🚨 P0 今日关注
  📊 本周变化汇总表
  🔍 各产品详细变化
  📈 趋势分析

⚡ 30 秒电梯陈述

"我用 Claude Code 搭建了一套 AI-native 竞品情报系统。核心思路是把竞品监控拆成 5 个独立 Skill——采集、提取、蒸馏、索引、报告——每个 Skill 可以独立优化。系统底层是 MCP 工具链，包括浏览器自动化、视觉识别、文档解析。信息入库后通过三层知识架构管理，配上 Spec 约束规则保证质量。当需要同时盯 5 家产品时，5 个 Agent 并行采集，3 分钟完成一个人要 1 小时的工作。整套系统跑在一个自建的 Harness 框架上——有执行层、记忆层、反馈层、编排层四层架构。"

常见追问准备

Q："这和用 ChatGPT 一个一个问有什么区别？"

三个区别。第一，ChatGPT 没有记忆，每次从零开始；我的系统有三层知识架构，越用越聪明。第二，ChatGPT 不能操作浏览器、不能读图、不能并行调度多任务；我的 MCP 工具链全链路自动。第三，ChatGPT 没有 Spec 约束，输出质量不稳定；我的 Spec 保证每次输出结构化、可对比、可追溯。

Q："搭建这套系统花了多长时间？"

"初始版本用了大约一周，主要是设计 Skill 拆分和 Spec 规则。但关键是——搭建完后，每次采集只需要说一句话。从手工 1 小时到自动 3 分钟，投入产出比非常高。"

Q："你在其中具体做了什么？"

"三个核心工作：一是设计了 5 个 Skill 的能力边界和接口规范；二是定义了 Spec 约束规则（去重/分级/时效/格式）；三是搭建了三层知识架构（框架知识常驻 + 轻量索引 + 原文存档）。代码执行是 AI 完成的，但架构设计和规则定义是我主导的——这就是 AI 运营岗的核心能力：不是写代码，而是设计 AI 的工作方式。"

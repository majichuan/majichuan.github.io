📋 项目概况

📥 输入

一份 22.62 MB 的英国在线零售商 Excel（541,909 行 × 8 列），涵盖 2010-2011 年跨国交易明细——客户ID、国家、商品描述、数量、单价、日期等

⚙️ 处理

严格遵循 12 步流程（A1-A7 数据分析 + B1-B5+ PPT 构建），通过 Python 流式读取→数据质检→多维分析→matplotlib 图表→JSON 驱动 PPTX 引擎→SlideViber SVG 美化

📤 输出

① 自包含 HTML 数据分析简报（ECharts 图表嵌入） ② python-pptx 原生可编辑 PPT（3 张图表） ③ SlideViber 演示级美化版 PPT ④ 一套可复用的 Skill 体系（12 步规范 + PPT 引擎 + 10 套主题）

1 原理和流程

用业务语言理解这个 Skill 的设计理念——类比：一条从"矿石"到"精炼品"的数据加工流水线

这个 Skill 到底解决了什么问题？

运营工作中有一个高频痛点：手里有数据，老板要 PPT。从原始 Excel 到一份能拿得出手的汇报 PPT，中间有大量重复性劳动——读数据、洗数据、算指标、拆维度、做图表、写洞察、排版……每一步都要花时间，而且容易遗漏或出错。

这个 Skill 的本质是：把"数据分析→PPT 汇报"这条完整的知识工作流，固化为一套 AI 可执行的标准操作流程（SOP）。12 个步骤环环相扣，每一步有明确的输入、输出和质量标准。AI 不再"凭感觉"做数据分析，而是像工厂流水线一样严谨执行。

类比一下：传统的做法像手工作坊——每次接到任务，从头开始想怎么做，靠个人经验，质量不稳定。这个 Skill 像标准化生产线——每个环节有 SOP、有质检、有工具链，换不同的人（甚至不同的 AI）执行，产出质量一致。

整体工作流程：A 段（数据分析 7 步）+ B 段（PPT 构建 5+1 步）

🔍 点击展开：每一步的详细解释

A1 读取与理解：使用 iterparse 流式读取超大 Excel（54 万行），避免内存溢出。输出每一列的业务含义映射表，标记不确定的字段。这一步解决了"拿到数据先乱做"的问题——先理解数据在说什么。

A2 数据质检：检查四类问题——缺失值、重复、异常值（零/负/极端值）、时间字段。每项标注严重度（🔴/⚠️）和处理方案。这是最容易被跳过的步骤，但脏数据会污染所有后续分析。

A3 核心指标：应用 A2 的清洗规则，计算总销售、订单数、客户数、客单价、SKU 数等。每个指标必须可复现，排除条件可追溯。

A4 多维拆解：按时间/地区/产品三个维度拆解，Top N 排名 + per-unit 指标。每个维度必须有判断句——"量驱动还是价驱动？""集中还是分散？"

A5 趋势与异常：月/周时序分析——趋势方向、季节性、离群值。扫描负销售、零价格、高退货率。每个异常必须解释业务含义。

A6 图表生成：2-4 张 matplotlib 图（非 8 张！克制精选）。线图→时间序列，水平柱→排名，分组柱→比较。⚠️ figsize 必须匹配 B5 layout 容器宽高比。

A7 执行摘要：自包含 HTML 文件，960px 居中，5 部分结构（核心结论/指标卡片/重点发现/建议动作/图表附录）。老板读完能做决定。

B1 字段→问题映射：把技术字段翻译成业务问题。例如 Quantity+UnitPrice → "哪些产品贡献了最多收入？" → 条形图页面。

B2 幻灯片骨架：8-10 页叙事序列，逻辑线：现状→结构→机会→打法。每页一个判断式标题，标题连读成一个完整故事。

B3 图表审计：逐一审计：时间→折线，对比→柱状，排名→条形，占比→饼图（≤5 类）。不匹配则替换并给出理由。

B4 业务语言翻译：最关键的一步——把数据翻译成业务判断。每页选择最适合内容的 layout（8 种可选），写 1-2 条"关键解读"（说所以呢）+ 可选"行动建议"（说然后呢）。连续页不得重复 layout。

B5 PPTX 生成：存为 JSON 配置，选主题（10 套），运行 build_pptx.py。输出可编辑 .pptx，中文无乱码，图表嵌入无变形。

B5+ SlideViber 美化：可选步骤。用 SVG 重绘幻灯片，21 套主题可选，浏览器实时预览，原生 PPTX 导出。但只美化不改内容。

流程设计的核心巧思：A/B 两段分离 + 执行顺序铁律

A 段：数据分析B 段：PPT 构建

2 核心难题

从这个项目的第一版执行到最终打磨完成，遇到的 7 个关键问题和难点

难题 1 图表完全缺失——PPT 里只有表格，没有图表

第一版 PPT 生成后，用户打开发现没有任何图表——所有分析维度都是纯文字表格。根因是：A6（matplotlib 生成图表 PNG）和 B5（图表嵌入 PPT）这两步被完全跳过。AI 直接从 A5 的文字分析跳到了 PPT 的文字排版。12 步流程中有两个关键步骤被"省略"了，但 AI 没有意识到这是致命的。

难题 2 图表拉伸变形——两次出现，两个根因

第一次（build_pptx.py 阶段）：matplotlib 默认 figsize=(10,5)（2:1），但 build_pptx.py 的 layout 容器宽高比各不相同（wide=2.88:1, insight-action=2.42:1, side=2.16:1）。2:1 的图塞进 2.88:1 的容器→横向拉伸 44%。

第二次（SlideViber 阶段）：修复 build_pptx.py 后，美化的 SVG 中 <image> 容器宽高比又不匹配了——SlideViber 的 PPTX 导出器不认 SVG 的 preserveAspectRatio 属性，强制按容器尺寸拉伸。同一个问题，不同的根因，修了两次。

难题 3 输出格式错误——Markdown 而非 HTML

用户明确要求"数据分析简报要生成 HTML 格式"。但第一版输出的是 Markdown 文件——没有图表嵌入、没有 KPI 卡片、没有专业排版。AI 默认选择了"最省事"的输出方式，而不是"最合适汇报"的方式。这是 AI 的一种惯性：能省则省，除非被明确约束。

难题 4 两个 AI 共享知识——Codex 和 Claude Code 各自维护规则

这个 Skill 最初由 Codex 创建，Claude Code 协助落地执行和调试。但两边的 memory 各自维护——Codex 有 skill 定义，Claude Code 有执行 memory。同一个 12 步流程在两端以不同形式存在，信息重复且容易不一致。改了 A 端漏了 B 端 → 下次 B 端执行时读到旧规则 → 重复犯错。

难题 5 SlideViber 内容篡改——美化≠重写

第一次 SlideViber 美化后发现 6 个具体问题：文字溢出容器、缺少行动建议板块、洞察和行动混在一个块里、使用口语化标签（"所以呢""然后呢"而非"关键解读""行动建议"）、内容不完整（部分段落被省略）。AI 在"美化"的过程中忍不住"帮你改"——这是所有生成式 AI 的通病。

难题 6 Memory 文件膨胀与重复

同一个主题建了多个 memory 文件——大表哥文章处理建了 4 份（SOP / 清单 / 工作流 / 存档规则），12 步流程信息在 memory 和 SKILL.md 中重复出现。文件越多，调用效率越低；信息重复时改一处漏改另一处→调用时拿到矛盾信息。这是"每次遇到新问题就新建一个文件"的习惯导致的系统性债务。

难题 7 Excel 太大——22MB 超出所有常规工具的处理上限

54 万行 × 8 列的 Excel 文件，MinerU 无法处理（超出文件大小限制），Windows COM Excel 接口调用失败。最终只能安装 Python 3.12 + pandas + openpyxl 直接流式读取。这暴露了一个通用问题：AI 工具链对于"大文件"场景缺乏统一解决方案，需要根据实际情况灵活切换技术栈。

3 解决方案

每个难题的对应方案，以及背后的设计思路——不只修 Bug，要修流程

方案 1 12 步流程铁律 + 交付前自检清单（治本之策）

对应难题 1 和 3。不是"提醒 AI 别忘了做图表"——而是建立两个机制：① 12 步不可跳步：把每步的"输入→做什么→产出→质量标准"写成结构化表格，AI 执行时必须逐行走完。② 交付前自检清单：HTML 简报 8 项 + PPT 8 项，逐项打勾后才能交付。其中 PPT 第 2 项就是"图表嵌入（非纯表格）"——这个检查项专门防止图表遗漏。

旧方案（无流程约束）新方案（12 步 + 自检清单）
图表生成AI 自己决定要不要做A6 强制步骤，有明确产出标准
图表嵌入可能被跳过B5 必须嵌入，自检清单逐项验证
输出格式AI 默认 MarkdownA7 强制 HTML 自包含单文件
交付质量凭感觉判断16 项自检清单全部通过才交付

方案 2 figsize 速查表 + 执行顺序铁律（关键创新）

对应难题 2。图表拉伸的根因是顺序错误——先定 figsize 再选 layout。正确顺序是：B2 确定每页 layout → 查速查表 → A6 用匹配的 figsize 生成图表。为此建立了速查表：

Layout容器 (inch)宽高比matplotlib figsizeSVG image 容器
wide12.1 × 4.22.88 : 1(11.52, 4.0)width="1800" height="625"
insight-action7.5 × 3.12.42 : 1(9.68, 4.0)width="1100" height="455"

同时覆盖了 SlideViber 的图表容器问题：height = width / 比率（通用公式）。SlideViber 的 PPTX 导出器不认 SVG 的 preserveAspectRatio 属性，必须确保 <image> 的 width/height 比率精确等于图表 figsize 比率。

方案 3 FRAMEWORK.md —— 两个 AI 的单一权威源（架构创新）

对应难题 4 和 6。核心洞察：不是"让两个 AI 互相通信"，而是"让两个 AI 读同一份文件"。建立了 FRAMEWORK.md 作为唯一共享权威源，包含：12 步表格（每步的"解决的问题"+"质量标准"）、流程依赖关系图、8 条关键规则、figsize 速查表、常见错误表、3 条行为规则。通过 Junction 目录同步，Codex 和 Claude Code 都能直接读写。

设计原则：所有通用规则（流程、行为约束、质量标准）直接写入 FRAMEWORK.md。仅当规则涉及某个平台特有的功能时才写入该平台的本地 memory。Claude Code 的 memory 从"内容副本"变成"指针"——指向 FRAMEWORK.md + 补充平台专属规则。

方案 4 SlideViber 协作铁律——内容 vs 美化的明确边界

对应难题 5。制定了严格的协作铁律：build_pptx.py 产出的 PPT 内容是权威（single source of truth），SlideViber 只做视觉美化，不修改任何内容。列出了详细的"允许/禁止"清单——允许优化布局/配色/字体/间距/视觉层级，禁止修改标题/洞察/行动建议文字、禁止增删内容板块、禁止使用口语化标签。

职责build_pptx.pySlideViber
标题/洞察/行动文字✅ 权威❌ 不修改
数据/KPI 数字✅ 权威❌ 不修改
图表 PNG✅ 权威❌ 不重新生成
页面结构（板块/顺序）✅ 权威❌ 不增减
布局/配色/字体/间距—✅ 优化
视觉层级（卡片/阴影/图标）—✅ 增强

方案 5 Memory 指针化 + 合并去重

对应难题 6。两条规则：① 尽量少建文件，一个主题一个文件——能在已有文件里加一段解决的，绝不新建文件。② 单一信息源——同一类信息只在一个文件中维护。大表哥文章处理 4 份文件合并为 1 份，12 步流程 memory 从内容副本改为指针（指向 FRAMEWORK.md）。每条 memory 都有"为什么"和"如何应用"字段，防止规则变成僵尸。

方案 6 Python 替代方案 + 工具选择规则

对应难题 7。22MB Excel 超出 MinerU 限制 → 安装 Python 3.12 + openpyxl + pandas 直接流式读取。这件事还催生了另一个规则：接到任务先扫 MCP 工具，别惯性用 Read——比如用户提供截图时优先用 OCR 专用工具而非 Read 读取图片。

4 优化方向

基于当前方案，从四个维度看未来的优化空间——哪些可以做得更好？

🔧 维度一：流程方法论优化

📋 A7 简报 → B2 骨架：打通"分析结论→PPT 叙事"的自动映射

当前 A7 简报的结论和 B2 的页面骨架之间是手工映射的——AI 读了 A7 的结论，再手动规划 B2 的 8-10 页结构。下一步可以让 AI 自动从 A7 的结构化结论中推导出 PPT 页面序列：核心结论→封面标题，重点发现→图表页，建议动作→行动页。减少人工翻译环节，提高一致性。

🎯 A6 图表智能推荐：根据数据特征自动选图类型 + layout

当前 B3 图表审计是"事后检查"——先选了类型再审计是否合理。可以升级为事前推荐：AI 分析数据特征（趋势/对比/排名/占比），自动推荐最佳图表类型 + 对应 layout + figsize，人工只需确认而非从头选择。

🔄 多轮迭代模式：用户反馈→自动修正

当前是"一次性生成→用户手动提修改"。可以改为对话式迭代：生成初版→用户说"第三页图表太大了"/"标题不够有力"→AI 只改那一页的 JSON 配置→重新生成。局部的改，不重跑全流程。

💡 流程方法论层面的更多优化思路

1. 数据画像前置——在 A1 读取阶段就生成一份"数据画像"（行数/字段类型/缺失率/分布特征/建议关注维度），作为后续所有步骤的快速参考。AI 不需要每次都重新扫描整个数据集。

2. 中间产物持久化——将 A3-A5 的中间分析结果存为结构化 JSON，B 段直接从 JSON 读取而非重新计算。好处：① 避免重复计算 ② 换人/换 AI 执行时可以直接接续 ③ 中间结果可审计。

3. 模板库积累——每次做完一个项目，把 B4 的页面内容和 B5 的 JSON 配置保存为模板。下次遇到类似数据（如"电商月度报表"），直接加载模板+替换数据，从"每次从头做"变成"选模板再微调"。

🤝 维度二：双 AI 协作体系优化

🔗 FRAMEWORK.md 版本控制：像 Git 一样追踪规则变更

当前 FRAMEWORK.md 是最新版本，但没有变更历史——不知道某个规则是谁改的、什么时候改的、为什么改。下一步可以：每次修改 FRAMEWORK.md 时自动记录变更日志（日期/修改人/修改内容/原因），方便回溯和审计。当发现某条规则导致问题时，可以快速定位是哪个版本引入的。

🧪 规则变更的回归测试

选取 2-3 个"标准数据集"（如本次的 Online Retail），每次修改 FRAMEWORK.md 或 SKILL.md 后，自动用新规则重新跑一次完整 12 步流程，对比新旧输出的差异，确保"优化"没有引入新问题。类似软件工程中的回归测试，但测试对象是 AI 执行流程的质量。

🔄 Codex 和 Claude Code 的能力互补矩阵

当前已知两个 AI 的能力差异（Codex 原生支持文档插件和 Goal 系统，Claude Code 有 Workflow 多 Agent 编排和 Playwright），但还没有系统化的"分工指南"——哪些步骤更适合 Codex 执行、哪些更适合 Claude Code 执行。建立能力互补矩阵后，可以把一个 12 步任务拆分给两个 AI 各自执行最擅长的部分。

🛡️ 维度三：质量保障体系升级

📊 自动化自检脚本

当前自检是 AI 手动对照清单打勾。可以开发一个 Python 脚本，自动验证：PPTX 中图表数量 ≥ 2、每张图片宽高比与对应 layout 匹配、HTML 中图表数据非空、中文编码无乱码等。机器检查不遗漏，AI 专注于需要判断力的项目。

🔬 图表拉伸自动检测

在 build_pptx.py 中增加一个后处理步骤：读取 PPTX 中每张图片的实际宽高比，与 figsize 速查表中对应 layout 的预期宽高比对比，偏差超过 1% 则报警。把"人工目测"变成"机器自动检测"。

✅ B4 洞察质量评分

用 LLM 自动评估每条"关键解读"的质量：是否在说"所以呢"（而非"如图"）、是否引用了具体数据、是否说明了业务意义。低于阈值的洞察自动标记为"需人工复核"。

🏗️ 维度四：技术架构优化

📦 build_pptx.py 独立化

当前 build_pptx.py 依赖 skill 环境运行。可以封装为独立的 pip 包 + CLI 工具，不依赖任何 AI——任何有 Python 环境的人都能用，JSON 驱动、10 套主题、零编码。让这个工具的受众从"AI 用户"扩展到"所有做 PPT 的人"。

🌐 Web 界面

基于 build_pptx.py 的 JSON 配置开发一个 Web 编辑器——拖拽选择 layout、填写洞察文字、上传图表、实时预览。降低使用门槛，让不会编程的运营同事也能用。

📱 数据源扩展

当前只支持 .xlsx 输入。可以扩展为支持 CSV / JSON / 数据库直连 / Google Sheets / 飞书多维表格——覆盖运营工作中实际会遇到的各类数据源。

5 业务应用

从 Online Retail 案例延伸到互联网运营工作——怎么把这套方法论应用到实际业务中？

核心迁移逻辑："Excel→数据分析→PPT"这套 12 步流程，本质上是一套"从原始数据到决策汇报"的标准化生产线。把"Online Retail 交易数据"换成"运营活动数据/用户行为数据/竞品数据"，整个 pipeline 可以直接复用。价值不在于处理了这一次的 54 万行数据，而在于下次、下下次、任何数据分析+PPT 任务都有了可复用的流程和工具链。

📊 场景一：运营周报/月报自动化

👤 个人/团队层面 · 运营岗最高频需求

实际问题

运营同学每周/每月都要写数据报告——从后台导出 CSV、Excel 里做透视表、截图贴到 PPT 或飞书文档。同样的流程重复 52 次/年，每次耗时 1-2 小时。这种高重复性的劳动完全应该被自动化——人只需要在最后做判断和润色，而不是每次都从零开始。

💡 方法论

AI 执行复杂任务，关键不在于 AI 有多聪明，而在于流程设计有多严谨。12 步流程、figsize 速查表、交付前自检清单——这些都是"防呆设计"，把 AI 容易遗漏、容易犯错的地方用结构化规则堵住。流程设计能力比 prompt 技巧重要得多。

🛠️ 工程化

把一次性的"帮我看数据做 PPT"变成可复用的 Skill 体系——FRAMEWORK.md 是大脑（流程规范），SKILL.md 是手册（执行细节），build_pptx.py 是工具（代码引擎），memory 是备忘录（经验教训）。四个组件互相配合，缺一不可。

🚀 可迁移性

这套方法论的核心模式——"输入→清洗→分析→可视化→洞察→输出"——不只适用于 Excel→PPT。任何"从非结构化信息中提炼可呈现的洞察"的场景（竞品追踪、用户反馈、实验复盘、渠道分析），换内容源即可复用，流程不变。

🎓 对 AI 工具的本质理解

这次项目让我深刻体会到：AI 不是"帮你省掉思考"的工具，而是"帮你的思考聚焦在真正需要人的判断的地方"的工具。AI 擅长的是：按规则执行重复操作、生成结构化输出、不遗漏检查项。人擅长的（而且应该聚焦的）是：判断数据背后的业务含义、做出策略性决策、理解老板真正的关切。好的协作不是"人告诉 AI 怎么做"，而是"人设计流程让 AI 可靠执行，人聚焦在 AI 做不到的判断上"。

30 分钟精读助手

从“如何在有限时间掌握一本书”出发，把 Agent、模型生成和 HTML 阅读界面组织成一条用户可理解、可行动的产品链路。

体验原型用户任务完整产品链路
USER TASK / 01

用户任务

输入

只需要提供书名

降低开始阅读和整理问题的门槛，不要求用户先设计复杂提示词。

理解

先建立全书结构

围绕核心观点、关键章节和论证关系建立有限时间内的理解路径。

行动

把阅读转成下一步

输出不仅有摘要，也包含可执行的行动建议和延伸方向。

PRODUCT FLOW / 02

产品链路

  1. 01输入书名用户任务
  2. 02Agent 结构组织输出框架
  3. 03模型生成形成结构化方案
  4. 04HTML 阅读界面承载理解与行动
INTERFACE / 03

界面与使用方式

下面使用实际产品的两张完整界面，分别展示如何找到一本书，以及选中书后如何完成结构化精读。点击图片可查看原尺寸。

找书入口

输入书名或作者

搜索、书架和热门推荐共同降低开始门槛。

结构化精读

用六段结构组织内容

先建立框架，再阅读洞见、金句、行动和延伸内容。

阅读与行动

边读、边记、边追问

笔记与 AI 讨论留在同一界面，让理解继续转成行动。

ROLE / 04

我的角色

用户任务

定义“30 分钟掌握一本书”

明确产品要帮助用户完成的任务，而不是从模型能力出发堆功能。

输出结构

确定内容层级和阅读顺序

让核心观点、金句、行动指南和延伸推荐形成稳定结构。

交互体验

把模型结果变成可阅读界面

围绕输入、等待、阅读和继续探索设计完整体验。

验收判断

检查是否真的帮助理解

AI 协助实现，我负责判断内容结构、交互和结果是否符合用户任务。

OUTPUT / 05

输出结构

核心观点

先掌握作者最重要的判断

用结构化表达降低长文本的理解负担。

金句与案例

保留关键表达和支撑关系

帮助用户理解观点如何被论证，而不是只得到一句摘要。

行动与延伸

从阅读进入实践

提供行动指南和延伸推荐，让学习形成后续路径。

BOUNDARY / 06

当前边界

当前状态

可使用的体验原型

本案例证明从需求定义到可使用界面的完整产品实践。

公开范围

展示机制，不冒充公开上线
